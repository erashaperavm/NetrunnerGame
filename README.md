《Netrunner Rulebook》v1.2

定位：沉浸式真实网行者攻防模拟器（单机）
受众：有网络骇入基础的赛博朋克爱好者
核心承诺：你指挥 Scorpion Agent 做的，是真实的模拟骇入——真实 microVM、真实防火墙、真实攻防 Agent，全部发生在本地隔离虚拟网络内。

v1.2 变更摘要：明确网络地址采用 Base32 标识而非 IP 地址；快速移动过场采用区域分片、多交通工具与多天气素材，并将数秒级片段拼接为连续播放；移除 0.5 秒追踪查表频率建议，明确图像识别阶段以设定时长的 sleep 占位，不接入真实图像 AI；新增现实层已遭追踪并开始被骇入的危机，以及玩家组织 Agent 反击的玩法；新增快速移动碰撞、行人伤害、到达延迟与 NCPD 通缉/对抗/贿赂机制。

第 0 章 设计公理

四条不可违背的公理，全书所有规则都从这里派生。

1. 真实优先：目标服务、防火墙、Key 文件、攻防 Agent 都是真实存在的软件实体，不是数值模拟。
2. 安全隔离：所有 microVM 处于本地虚拟网络内，零公网流量。游戏世界中的网络地址使用 Base32 字符串标识，不呈现为 IP 地址；底层隔离网络的寻址实现属于内部细节，不作为玩家可见的世界观地址。EULA 写死。
3. Agent 干苦活，玩家做决策：Scorpion 自主执行侦查/枚举/试探；model.Question 在分叉、风险、异常、资源临界点请求玩家决策，节奏为几十秒一次。
4. 成本可见：默认 API 模式，游戏内实时显示 token 消耗与预估成本；提供经济模式（全员 Agent 降级 + 弱 ICE）。

第 1 章 世界与叙事框架

赛博朋克 Night City 世界观。玩家是一名网行者（Netrunner），通过地图快速移动抵达目的地、选择藏身处、通过队员视角远程接入目标。故事开始时，玩家和队友接受委托，进行一些 RPG 对话以及选择，选择可能会影响后期队友信任、社会威望，然后快速移动到适合的位置进行骇入以完成任务，可以骇入带图像呈现的目标（队友连接即可，无需骇入，除非队友已经背叛）来远程骇入，敌方若侦测到，则开始入侵现实侧的设备、基础设施或玩家控制节点；玩家必须组织并调度自己的 Agent 进行侦查、隔离、反制与反击。

叙事层与机制层解耦：RPG 对话提供动机与后果，所有骇入发生在第 10 章的本地虚拟拓扑内。队友、帮派、NCPD 的"记忆"由第 9 章的信任值系统驱动。

移动方式：不提供手动驾驶。玩家在地图上点击目标位置即触发快速移动，播放预录制的过场驾驶镜头（详见第 6.5 节）。

第 2 章 核心循环

```
[物理层] 骇入他人被发现 → 现实环境遭追踪/骇入 → 组织 Agent 反击；地图点击节点形成路线 → 快速移动（分片过场镜头 + 路程百分比 + 碰撞风险）→ 藏身 → 接入
   │                              │
   │                              └→ 敌方追踪 / 交通封路反制
   ▼
[赛博层] 获取相关 Skills KBs Tools（Shark）→ 渗透（Scorpion+ToolRT）→ 取 Key → 施展快速破解
   │                              │
   │                              └→ 敌方防御 Agent 反制（升级防火墙/反攻/溯源）
   ▼
[决策层] model.Question 每隔几十秒弹出关键决策
   │
   ▼
[宏观层] 骇入城市网络/NCPD/公司网络 → 调度外部力量 → 连锁反应
```

物理层与赛博层并行：快速移动期间 CyberspaceGUI 悬浮于视角内，玩家可继续骇入（详见第 6.5、12.2 节）。物理时钟与赛博时钟同时运转（详见第 6.2 节）：玩家在赛博空间停留的每一秒，三角定位进度在涨；骇入越快，物理越安全。

第 4 章 队友系统

类型：螳螂刀手、飞刀手、武士、重炮、狙击手、突击手。Solo 或 1~2 名队友。

队友是 AI 驱动：每名队友是一个独立 Scorpion 实例，有独立 Role、独立权限沙箱、独立 FOU 流。这是"背叛机制"成立的前提——队友 Agent 会在 Secure 裁决（model.Secure 会在极端危险下优先自保）中选择"不服从"，而非脚本触发。

队友权限沙箱（底层）：每名队友在 Krab 内拥有独立 workspace + 按 ACL 表生成的只读挂载视图。未授权路径不挂载，即使队友 Agent 绕过 Scorpion 直接 syscall 也碰不到。

队友与快速移动：快速移动时队友同车，可在过场镜头中以对话/动作形式出现；队友的信任值受"移动途中是否停车救援/是否绕路"等决策影响（详见第 9.2 节）。

5.3 ICE Mod Schema

```yaml
ICEMod:
  id: string
  archetype: enum          # embedded-min | embedded | human-augment | enterprise-lite | enterprise | blackwall
  tier: 0.5~5.0

  layers:                  # 只列出该原型真实存在的层
    - layer_type: enum     # perimeter | host | auth | app | detection | response
                           # 或 embedded 原型的：exposed_service | firmware | physical_bus
                           # 或 human-augment 原型的：near_field | augment_firmware | bio_monitor
      reality_components: [string]   # 现实对应物，见上表
      protocol: string
      key_fragments: int
      regen_rate: duration           # 被窃后重生成速率（BODY 对抗）
      exploit_surface: [cve_id]

  key_fragments:           # 分类的凭据，对应真实凭据形态
    - kind: enum           # credential | token | cert | config
      location: string     # fs 路径 / 内存 / 日志 / 环境变量
      layer: int           # 属于哪一层
      stolen: bool

  countermeasures:         # 反击规则（L1 规则引擎执行，对应 detection/response）
    - trigger: condition
      action: enum
      cooldown: duration

  heuristics:              # 预算/降级时的基线策略
    alert_threshold: float
    upgrade_policy: enum
    counter_priority: enum

  human_in_the_loop:       # enterprise / enterprise-lite 独有
    enabled: bool
    response_delay: duration   # 模拟 SOC 值班反应窗口

  persona: string          # 给 LLM 的人格上下文
  model_tier: enum         # 敌防御 Agent 使用的模型等级
```

countermeasures 与 heuristics 是同一逻辑的两个精度。Agent 可用时由 LLM 决策“何时升级/何时反击”；降级时直接查 heuristics 表。

· archetype 决定 layers 的合法集合——加载器应拒绝“人形单位挂 perimeter 层”这种非法组合。
· key_fragments 带 kind 和 layer，这样“拼合 Key”有真实语义：收集不同层的凭据（credential/token/cert/config）组合成访问链，而不是找拼图。
· human_in_the_loop 只给企业原型：触发告警后有 SOC 响应延迟窗口，玩家可抢在窗口内完成利用。

玩家 microVM 同样挂载 ICE Mod（按玩家接入点的 archetype），攻防对称不变。

第 6 章 赛博空间战斗与物理层移动

6.1 微观对抗（单个敌对单位）

每个敌对单位 = 一个 microVM（真实服务 + nftables + ICE Mod 守护进程 + 防御 Agent 客户端）。玩家破解的是真实配置：防火墙规则真实生效，Key 文件真实存在于 fs，防御 Agent 真实读日志改规则。

流程：

1. Scorpion 侦查（Shark 检索已知漏洞/同类 ICE 记录，TECH 决定查询速率）
2. Scorpion 渗透（ToolRT 执行真实工具，固定版本：nmap/自研 exploit/代理客户端）
3. 破解防火墙 → 在目标 fs 找 Key 碎片 → 拼合 → 获得 Control Key
4. 用 Key 施展快速破解
5. 敌防御 Agent 同时：升级防火墙、发起反攻（窃取玩家 Key）、溯源

成功标准：破解防火墙 + 找到并拼合 Key 文件。敌方成功标准相同（对玩家做同样的事）。

6.2 双时钟

· 赛博时钟：真实攻防耗时。
· 物理时钟：由两部分组成——① 快速移动的到达进度（见 6.5）；② 三角定位进度条，随监控网络被敌方利用而增长。

玩家可骇入监控网拖慢定位进度——但拖慢本身消耗时间。核心权衡：骇入快 = 物理安全；移动快 = 定位风险低。

6.3 并行侦查与援军标记

Scorpion 对当前敌人作战期间，可自主寻找其他骇入点（如监控网络）。一旦骇入监控网：

· 规则引擎（非 LLM）持续返回所有 visible 敌对单位在 Night City 的实时位置——visibility 含义眼透视、监控覆盖，只要在视线内即算。
· 援军被标记后，监控网追踪引擎按真实规则持续反馈位置，直到玩家失去监控权限。

实现要点：位置查询是监控 microVM 提供的接口，玩家 Agent 调用返回坐标；"visible"由渲染层视锥检测 + 监控覆盖判定，规则引擎每 tick 同步。这条链路不依赖 LLM。

6.4 代理链与身份隐藏

· 玩家先渗透多个接入点 microVM，建立多跳隧道（真实 SSH/WireGuard；游戏世界中以 Base32 网络地址标识节点，不向玩家暴露 IP 地址；底层全部走本地 bridge）。
· 溯源 = 某跳被敌方 Agent 攻破。身份暴露后，调度的 NCPD/公司力量会撤军或反攻玩家。
· 反追踪逻辑由规则引擎实现，不依赖 LLM：每跳的"污染度"是确定性数值，敌方溯源按规则推进。

6.5 快速移动与敌方追踪

6.5.1 快速移动机制（玩家侧）

· 操作：玩家在地图上点击目标位置即触发快速移动，无手动驾驶。
· 演出：播放预录制的过场驾驶镜头（2D 为动态插图/视差动画，3D 为预渲染视频或简化实时场景）。
· UI：画面下方显示"剩余到达路程：X%"，百分比随移动推进。
· 并行骇入：快速移动全程 CyberspaceGUI 悬浮于视角内，玩家可在移动中继续骇入（见 12.2）。
· 中断：玩家可随时中止移动（点击"停车"），中止后进入"静止接入"状态，物理时钟切换为三角定位模式（见 6.2）。

6.5.2 底层实现（确定性状态机）

```
FastTravelState {
  route: [segment_id],        // 路径规划结果
  percent: float ∈ [0,100],   // 到达路程
  base_rate: float,           // 基础推进速率（受载具/路段影响）
  modifiers: [               // 实时修正
    { type: "roadblock", segment, rate: 0 | negative },
    { type: "pursuit",   segment, rate: multiplier },
    { type: "collision_risk", segment, probability },
    { type: "weather", segment, rate: multiplier }
  ],
  wanted_level: int,          // NCPD 通缉等级/状态
  incident_log: [event_id]    // 碰撞、行人伤害、通缉等事件
}
```

· 每 tick：percent += base_rate × Π(modifiers)，到达 100% 触发抵达事件。
· 快速移动路线同时评估路段交通密度、行人密度、天气、载具特性与玩家 TECH 技术点数；这些因素共同决定碰撞风险，不由 LLM 临场随意判定。
· 封路（见 6.5.5）使该路段 rate 归零或为负（绕路），百分比可能停滞甚至回退。
· 快速移动是确定性规则引擎，不调 LLM。

6.5.3 敌方追踪链条（物理层对抗）

敌人若已骇入城市监控网络，则通过以下链条定位玩家：

1. 敌人骇入监控网络（敌人 Agent 的赛博行动，与玩家骇入对称）。
2. 敌人 Agent 推断玩家最可能片区（L2 LLM，低频：每 30 秒或每个路口触发一次）。
   · 输入：玩家最后已知位置、移动方向、道路网络拓扑、时间、历史模式。
   · 输出：候选片区列表（带概率）。
3. 规则引擎调用游戏 API 获取候选片区监控视角内元素（确定性查询）。
4. 若监控画面含玩家 → 猜测成功 → 监控系统进入图像识别判定阶段。
   · 图像识别目前不接入真实图像 AI；以预设时长的 sleep 模拟 AI 图像识别所需时间，sleep 结束后再由规则引擎根据模拟结果推进状态。
   · sleep 时长是明确配置项，不采用固定 0.5 秒作为默认值；实际识别精度与视觉模型能力不在当前版本实现范围内。
   · 识别成功后，监控系统自动追踪；自动追踪 = 查表处理：监控覆盖表（设备 ID → 覆盖区域） × 玩家实时位置，命中即追踪。
5. 若未发现 → 敌人 Agent 继续排查其他监控（回到步骤 2）。

关键分工：LLM 只做"片区推断"（低频、语义级），规则引擎做"画面查询"和"自动追踪"（高频、确定性）。这与"Scorpion 做苦活、玩家做决策"的分工一致。

6.5.4 与双时钟的关系

状态 物理层表现 敌方反制
静止接入 三角定位进度条增长 敌方通过监控网定位
快速移动（未被追踪） 百分比增长，定位风险低 敌方 Agent 周期性推断片区
快速移动（已被追踪） 百分比增长，但敌人持续获知位置 可能调度封路/派人拦截

· 已被追踪时，敌人持续获知玩家实时位置（查表结果），可触发封路或拦截事件。
· 玩家对策：加速（避开被封路段）、骇入监控网反制、骇入交通网解封、中途停车改换藏身点；也可调度 Agent 对追踪链、监控节点及敌方接入点发起反向渗透。

6.5.5 快速移动碰撞与 NCPD 通缉

· 快速移动并非无风险传送。路线规划阶段与移动过程中，系统根据玩家 TECH 技术点数、路线质量、路段实时人流/车流、天气及载具特性计算碰撞概率。
· TECH 越高，玩家越能规划更安全的路线、识别高风险路段并及时调整；TECH 不提供绝对免碰撞保证。
· 碰撞事件可能包括与其他车辆相撞、撞到路人。碰撞会造成车辆/人员事故，并延缓到达时间；延迟幅度由事故严重程度、现场交通阻塞及后续处置决定。
· 撞到路人时，存在触发 NCPD 通缉的概率；严重交通事故或其他目击/监控证据也可提高通缉风险。通缉判定由规则引擎根据事故、证据与区域执法响应结算。
· 触发通缉后，玩家需要选择对抗 NCPD 或贿赂 NCPD。对抗会带来追捕、交火及额外时间/资源成本；贿赂消耗资金，并可能因证据、执法等级或关系状态而失败/产生后续代价。
· 碰撞与通缉事件写入决策日志，影响到达时间、队友信任、帮派/NCPD 记忆与后续世界状态。快速移动仍由确定性规则引擎结算，不调用 LLM 决定随机结果。

6.5.6 交通封路

· 敌对单位可骇入城市交通网络实施封路（3 星目标，见 7.1）。
· 封路效果：快速移动百分比停滞，或被迫绕路导致回退。
· 玩家可骇入交通网络解除封路——与敌人争夺交通网络控制权，是赛博层与物理层的直接耦合。
· 争夺判定走规则引擎：双方对同一交通 microVM 的控制权由"谁最近一次成功写入 nftables 规则"决定，实时生效。

6.5.7 无手动驾驶的设计理由

· 手动驾驶与"沉浸式攻防模拟器"的定位冲突：驾驶操作会挤占玩家在赛博空间的决策带宽。
· 过场驾驶镜头保证叙事连续性，百分比 + 追踪 + 封路 + 碰撞/通缉提供物理层张力。
· 所有物理层决策都通过 CyberspaceGUI 和地图完成，不依赖驾驶技巧。

第 7 章 宏观网络

7.0 现实层入侵与 Agent 反击

· 开局时，玩家先骇入，敌方才开始反击；这不是单纯的背景叙事，而是持续推进的物理层/赛博层危机。
· 玩家需要组织自己的 Agent 编队，分配侦查、隔离、溯源、清除持久化、夺回节点与反向渗透等任务。
· Agent 的执行过程遵循核心分工：自主完成侦查与低风险处置；遇到高风险操作、权限变更、资源临界或策略分叉时，由 model.Question 请求玩家决策。
· 现实侧入侵目标与 Night City 内的本地隔离 microVM 对应。游戏仍不向公网发起真实攻击；所有攻防行为都在本地虚拟拓扑内模拟。
· 敌方入侵进度、玩家反制进度、节点控制权与可用 Agent 状态均应在 UI 中可见。

7.1 城市网络（3 星）

子系统 效果
交通 封锁道路（使快速移动百分比停滞/回退，提示重新规划路线）；解除封路；路线/交通信息可影响碰撞风险
监控 三角定位目标；可见单位实时位置反馈；快速移动中被敌方利用追踪玩家
水/电 耗尽敌方物资/断电

7.2 NCPD 调度中心（3 星）

可召唤 NCPD 或 MaxTac 攻击敌方。极高消耗：需同时对战多名敌对 Agent，且一旦被定位身份，调度会被撤销并反攻。

7.3 公司网络（4 星）

调度公司军队、调配物资资金。骇入创伤小组后，队员在其到达后获得回血。

7.4 黑墙网关（5 星）

释放流窜 AI。镇静 COOL 对抗意识侵蚀：侵蚀是渐进条，非概率事件。

7.5 流窜 AI 的实现

只要释放流窜 AI（取决于释放的数量），流窜 AI 会无条件攻击玩家、所有可破解目标，对于低难度的，不触发真实骇入逻辑，规则引擎直接判定成功。

第 8 章 死亡与失败

死法 机制 底层
① 被定位击杀 三角定位成功 → 敌方到来（可快速移动逃离，需对抗追踪与封路，敌人不会立刻到达） 物理时钟 + 敌方到场延迟 + 6.5 追踪链
② 赛博反击 Key 被窃 + 一定数量/伤害快速破解耗尽血量 敌方 Agent 真实完成攻破 + 施放
③ 黑墙/流窜 AI 自噬 意识侵蚀达阈值 侵蚀渐进条（COOL 抗性）
④ 队友背叛 取决于全程决策 信任值 + 队友 Agent 在 Secure 裁决中不服从

死法 ① 的逃离细节：被定位后玩家可立即触发快速移动。敌人不会瞬移，到场有延迟；但逃离途中敌人可调度封路、持续追踪。玩家需在 CyberspaceGUI 内实时反制（解封路/断监控）才能脱身。

第 9 章 持久化

9.1 经验

多次成功骇入 → 更快骇入。底层：降低敌对 Agent 的反击频率（经验积累让玩家 Agent 的侦查/利用成功率上升，敌方触发反击的条件更难满足）。

9.2 记忆

· 帮派敌对：路上无征兆攻击 = 帮派 microVM 的仇恨值持久化，进入其覆盖区触发（覆盖区包含快速移动路线上的帮派地盘）。
· 队友背叛：每名队友维护隐藏信任值，玩家每次决策（帮派冲突、救/不救、分赃、快速移动途中是否停车救援）微调。全程决策日志是必要条件——信任值由日志驱动，不可事后伪造。

9.3 存档与确定性

存决策日志 + seed，回放重放决策而非重跑模型。 否则读档后敌方行为全变，难度标签失效。快速移动的百分比推进、封路事件、追踪判定全部由规则引擎确定性执行，存档可完整重放。

第 10 章 底层架构

10.1 四模块总览

```
┌──────────────────────────────────────────────────┐
│  Scorpion Agent Server（编排/权限/决策）            │
│  Role: Question / Plan / Execute / Secure / Progress│
├──────────────────────────────────────────────────┤
│  Krab Linux（always-gVisor 沙箱抽象层）            │
│  每个 microVM = 一个 Krab 实例                      │
├──────────────────────────────────────────────────┤
│  ToolRT（执行 ABI：protobuf + 脚本引导文件）        │
├──────────────────────────────────────────────────┤
│  Shark（Skills/KBs/Tools/Web 检索）                 │
└──────────────────────────────────────────────────┘
```

10.2 Krab Linux

网络地址约定（世界观与实现边界）：
· 玩家可见的网络地址不是 IP，而是 Base32 编码的地址字符串；它是赛博朋克世界中的节点标识/寻址符号。
· Base32 地址用于 UI、日志、目标选择与叙事呈现。游戏内部隔离网络仍可使用实现层地址完成 microVM 通信，但该地址不作为游戏世界中的网络地址展示，也不改变“零公网流量”的安全公理。

· always-gVisor，默认 backend。所有 microVM 跑在 gVisor 内，syscall 在用户态内核拦截，FOU 采集结构化。
· FOU = 事务 = 审计单元 = ckpt 单元。FOU log 为 append-only（审计/回放），ckpt 为 CoW 快照（优先 gVisor 原生 C/R，fallback overlay+reflink）。
· ACL 下沉到 mount namespace：每个 Role 启动时按 ACL 表生成只读挂载视图，未授权路径不挂载。
· 网络：netstack 天然可审计可拦截。出口经 nftables，全部 local bridge，零公网。

10.3 Scorpion Agent Server

五个 Role，ACL 矩阵：

Role REQ PLAN 产物 SECURE PG
Question rw – – – –
Plan ro rw – – –
Execute ro ro rw – –
Secure ro ro ro rw –
Progress ro ro ro ro rw

· rw 仅 creator；ro 按依赖 DAG 授予。
· Secure = 宪法准入控制器：审核每次变更提案（聚合 N 个 FOU，非单 FOU）与每次 shell/网络请求是否符合 CONSTITUTION.json + REQ.json + PLAN.md。
· 两级：L1 规则引擎（OPA/CEL，毫秒，兜 80%）+ L2 Secure 模型（语义审查，秒级，审 20% 边界）。
· 防注入：FOU diff 作为结构化数据字段传入，system prompt 明确"待审数据非指令"。
· Secure 自身受最小权限约束：只读 workspace + 只写 SECURE.json。

API：tools.Fetch/Call、kbs.Fetch/Call、skills.Fetch/Call（Fetch=检索返回带 score/provenance 的候选；Call=执行/注入）。

10.4 ToolRT

· 对外 protobuf，对内 JSON：host 侧做转换，脚本只读写 fd 3/4，不要求脚本装 protobuf 库。
· 动态库：dlopen + protobuf ABI。
· 脚本：ps1/sh/lua/py 引导文件 + 可选动态/静态库，仅 Krab Templeace 临时封闭区域 rw，每次调用新建 + 销毁。
· 固定版本工具链：nmap/自研 exploit/代理客户端，沙箱内固定版本，保证可复现与合规。
· 资源限额走 cgroup。

10.5 Shark

统一 schema：Doc { type: skill|kb|tool|web, id, name, desc, tags, embedding, schema?, perms?, source, score, provenance }

· hybrid（BM25 + vector）+ rerank。
· 分类型召回：tool 重 schema 匹配、kb 重语义、skill 重触发条件、web 重时效。
· 游戏中 = 侦察玩法：骇入前检索目标公开信息/已知漏洞/同类 ICE 历史 → 降低后续难度。TECH 决定查询速率与深度。

10.6 microVM 编排

· Firecracker，每 VM 约 128MB 内存，单机 10~15 个可行（16GB 起步）。
· 每个目标 VM：真实服务 + nftables + ICE Mod 守护 + 防御 Agent 客户端。
· 玩家 VM：Scorpion + 固定工具链 + 代理客户端。
· 网关 VM：模拟"城市网络""NCPD""公司网络"，实为本地隔离网段。
· 交通/监控 microVM：为快速移动提供封路/追踪/交通流量与事故风险接口，规则引擎直接调用。
· 现实侧被入侵的设备/基础设施节点：作为玩家组织 Agent 反击的目标，提供隔离、清除持久化、夺回控制权与反向追踪等任务接口。

第 11 章 难度与配置

11.1 调控旋钮（仅四个）

旋钮 作用 默认
攻防 Agent 模型等级 推理强度（小/中/大） 按难度星级
Skills/KBs/Tools 调用速率 单位时间可发起操作数 技术属性
ICE Mod 初始等级 + 升级速度 防御强度 难度旋钮
反击触发阈值 防御 Agent 何时转反攻 镇静/难度

规则引擎不截断推理，只限速 + 分级。保留"真实"，同时可控。

快速移动相关参数：敌方 Agent 推断片区的频率（默认 30 秒）、封路触发概率、追踪查表执行频率、图像识别模拟 sleep 时长、路段碰撞风险参数、事故延迟参数与 NCPD 通缉判定参数。追踪查表本身由规则引擎执行；图像识别阶段以配置的 sleep 占位，不代表实际运行了图像 AI。

11.2 经济模式

全员 Agent 降级（小模型/本地模型），目标 microVM 挂载更弱 ICE Mod，速率限流。游戏仍成立，但"智力感"下降。作为可选项非默认。快速移动的规则引擎部分不受影响（本就无 LLM）。

11.3 确定性

固定 seed + 低温度（L2 LLM 调用）+ L1 规则完全确定。保证"3 星这局"与"下局"难度一致。快速移动的百分比、封路、追踪查表全部确定性，可完整回放。

第 12 章 交互设计

12.1 model.Question 决策

· 触发：分叉点、风险点、异常点、资源临界点。节奏几十秒一次。
· 呈现：文字描述 + 2~3 个方案对比（含预估代价/风险）。不做开放问答，紧张对抗中开放问答拖慢节奏。
· 自主度：Scorpion 在玩家不干预时只做侦查类（扫描/指纹/枚举/找接入点），不做利用类。利用必须玩家决策——否则玩家失去指挥官定位。

12.2 等待期处理与 CyberspaceGUI 悬浮

· Scorpion 在等待时自动执行合法但耗时的操作，玩家只看到汇总结果 + 决策点。避免进度条黑洞。
· 快速移动期间 CyberspaceGUI 持续悬浮于视角内，作为 HUD 层叠加在过场驾驶镜头上：
  · 玩家可在移动中继续骇入操作（侦查、渗透、反制封路/追踪）。
  · model.Question 决策面板在移动中同样弹出。
  · 物理层（地图、百分比、追踪警告）与赛博层（GUI、Agent 状态、决策）在同一个屏幕上共存，构成"边开车边网战"的核心体验。
· UI 布局建议：过场镜头占主视区，CyberspaceGUI 半透明浮于其上，底部为路程百分比条与追踪/封路告警条。

12.3 真实感的边界

· 不做真 TCP 栈模拟，坚持抽象层（端口/ICE/Key 碎片），受众有基础不代表想打真实包。
· 三层可选深度：表层（图形化）、中层（抽象指令如 scan/exploit/pivot）、深层（真终端玩家可见"这步对应 nmap -sV"注解）。

第 13 章 美术与资源

· 2D 优先：围绕"网络拓扑可视化 + Agent 状态 + 决策面板"设计，非角色扮演。
· 过场驾驶镜头：快速移动的演出资源。按地图区域分片，并为各区域准备多种交通工具、天气与交通状态的镜头素材；路线由对应区域片段组合。每个片段为数秒级短镜头，按路线顺序拼接并连续播放，形成类似幻灯片/动态分镜的快速移动演出，避免为每条路线单独录制完整视频。2D 阶段可用动态插图/视差动画，3D 阶段可替换为预渲染视频或简化实时场景。
· 2077 资源：发布后增强，用户本地从已安装的 2077 提取（WolvenKit/CP77 Tools），游戏本体绝不附带任何 CDPR 资产。EULA 明确：提取由用户自行完成，仅限本机，禁止再分发。不提供任何一键下载捷径。
· 2D 是产品基线，3D 是可选皮肤。过场驾驶镜头的 3D 版本属于 2077 资源增强的一部分。

第 14 章 待定项（开发中拍板）

1. Base32 网络地址的字符串格式、长度、校验与命名空间规则。
2. 经济模式最低配置下游戏是否完全成立（建议成立，智力感下降）。
3. 2077 资源提取的合规细则（法务介入）。
4. 区域分片镜头的素材覆盖范围：各区域需要覆盖哪些交通工具、天气、时段与交通状态组合。
5. 图像识别模拟 sleep 的默认时长与可配置范围；当前不实现真实图像 AI，不能把 sleep 描述为实际识别。
6. 快速移动中被追踪时的 UI 告警强度：是否显示敌人具体位置，还是只显示"已被追踪"？建议初期只显示状态，保留紧张感。
7. 碰撞、行人伤害与 NCPD 通缉的概率曲线、事故延迟、贿赂成本及失败后果。

一句话总结： 这是一款以 Scorpion/Krab/ToolRT/Shark 为底座的沉浸式攻防模拟器——真实 microVM、真实防火墙、真实攻防 Agent，全部封闭在本地隔离网；Scorpion 做苦活、每隔几十秒请玩家决策、规则引擎只限速分级不截断；快速移动替代手动驾驶，区域分片的多交通工具/多天气短镜头拼接 + 路程百分比 + 敌方 Agent 低频推断/规则引擎查表追踪 + 交通封路/碰撞/通缉反制 + CyberspaceGUI 全程悬浮，让物理层与赛博层真正并行；现实层开局已遭追踪与入侵，玩家需要组织 Agent 反击；四条死法、五属性、队友 AI 驱动背叛、代理链 fake IP 规则驱动、监控网络可见即追踪；2D 为基线，2077 资源为用户本地可选增强。所有设计服从第 0 章四条公理。
